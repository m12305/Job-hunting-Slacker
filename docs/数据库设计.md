# 数据库设计文档

> 数据库：SQLite（SQLAlchemy ORM 建模）。文件（PDF/Word/图片/录音）存本地目录。

---

## 1. 设计约定

- 所有表含主键 `id`（自增）。
- 通用时间字段（可选策略二选一，建议本地时间 UTC+8 或 ISO 存储）：
  - `created_at`：创建时间
  - `updated_at`：更新时间
- 枚举统一用小写英文字符串存储（前端映射中文）。
- 外键默认 `ON DELETE` 策略：主从明确的一律谨慎，采用 `RESTRICT` 或 `CASCADE`（见各表说明）。
- 标签类字段存 JSON 数组（SQLite 存 JSON 文本）。

---

## 2. ER 关系总览

```
job_types (岗位类型) 1 ── n resumes (简历版本)
resumes 1 ── n resume_logs (修改日志)
resumes 1 ── n applications (投递，缺省关联简历版本)

applications (投递) 1 ── n application_status_logs (状态流水)
applications 1 ── 1 offers (offer，一个投递最多一个有效 offer)
applications 1 ── n exams (笔试)
applications 1 ── n interviews (面试)

exams 1 ── 1 exam_reviews (笔试复盘)
interviews 1 ── n interview_qa (问答复盘)
interviews 1 ── 1 interview_results (面试结果)

materials (素材) ─ 独立
assets (资产) ─ 独立
questions (题库) ─ 独立
scripts (话术) ─ 独立
blacklist (黑名单) ─ 独立
tasks (每日任务) ─ 引用多种业务对象(ref_id + ref_type)
offer_weight_config ─ 独立配置(单行/多维度)
```

## 7. 索引建议

- 高频查询字段建索引：`applications(status)`、`applications(company)`、`applications(apply_time)`、`applications(job_type_id)`、`materials(category)`、`questions(category)`、`tasks(due_date, done)`。
- 单用户数据量小，非必需，但上述索引可提升体验。
