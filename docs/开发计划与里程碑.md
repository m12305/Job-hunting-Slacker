# 开发计划与里程碑

> 依据 PRD 拆解的开发任务、里程碑与验收标准。

---

## 1. 里程碑总览

| 里程碑 | 内容 | 产出 | 备注 |
|--------|------|------|------|
| M0 | 项目骨架 | 前后端脚手架、DB、基础设施 | 打基础 |
| M1 | 模块一：简历与资产 | 岗位类型/简历/素材/资产 | |
| M2 | 模块二：投递与 Offer | 投递/状态机/Offer 对比 | 核心 |
| M3 | 模块三：笔面试 | 笔试/面试/题库/复盘 | 与 M2 联动 |
| M4 | 模块四：数据统计 | 看板与图表 | 依赖 M2/M3 数据 |
| M5 | 模块五：其他 | 话术/黑名单/每日看板 | |
| M6 | 打磨与部署 | 导出/联调/测试/文档 | 收尾 |

建议开发顺序：M0 → M1 → M2 → M3 → M4 → M5 → M6（模块四依赖前三模块数据，可稍后）。

---

## 2. M0 项目骨架

**任务：**

- [ ] 初始化 backend（FastAPI + SQLAlchemy + Alembic + SQLite）。
- [ ] 统一响应封装、异常处理、CORS 配置。
- [ ] 数据库建模全部表 + Alembic 首版迁移。
- [ ] 初始化 frontend（Vite + Vue3 + TS + Element Plus + Pinia + Router + Axios）。
- [ ] 代理配置、Axios 封装、路由框架、布局骨架。
- [ ] `/api/health` 联通验证。

**验收：** 前后端可启动，健康检查通过，脚手架可跑通 CRUD demo。

---

## 3. M1 模块一：个人简历及资产管理

**任务：**

- [ ] 岗位类型 CRUD + 删除保护（有关联简历时阻止）。
- [ ] 简历版本 CRUD + 文件上传/下载 + 设默认版本。
- [ ] 简历预览：PDF 内嵌预览（分页/缩放/翻页）；Word 转 PDF 预览（需 LibreOffice 或本机 Word，缺失时降级为下载）。
- [ ] 简历修改日志（时间线）。
- [ ] 素材库 CRUD + 分类 + 标签 + STAR 结构化描述。
- [ ] 资产归档 CRUD（链接类 + 文件类） + 分类筛选。

**验收：** 可创建多个岗位类型、多版本简历、上传 PDF/Word、应用内预览 PDF（Word 转换预览或清晰降级）、录入素材与资产并筛选。

---

## 4. M2 模块二：投递全流程管理

**任务：**

- [ ] 投递记录 CRUD + 列表搜索筛选分页。
- [ ] 状态机（含合法流转校验）+ 状态流水时间线。
- [ ] 状态联动：进笔试/进面试时提供跳转入口。
- [ ] Offer CRUD + 薪资/城市/强度等字段。
- [ ] Offer 权重配置 + 打分算法 + 多 Offer 对比（含雷达图）+ 最优推荐。
- [ ] 投递时黑名单命中提示（依赖 M5 数据，可先用接口占位）。

**验收：** 可完整录入投递并流转状态；录入多个 Offer 并生成对比推荐。

---

## 5. M3 模块三：笔试面试全流程管理

**任务：**

- [ ] 笔试信息 CRUD（时间/平台/链接/账号密码）。
- [ ] 笔试复盘（通过率/题目/错题/考点/总结）。
- [ ] 面试信息 CRUD（轮次/时间/链接/自我介绍/准备清单）。
- [ ] 面试问答记录 + 复盘 CRUD。
- [ ] 面试结果（通过/挂掉/挂掉原因/录音上传）。
- [ ] 题库 CRUD + 分类/难度/标签 + 待刷/掌握标记。
- [ ] 与投递记录的关联与跳转。

**验收：** 从投递跳转创建笔试/面试，完成复盘闭环，题库可归档。

---

## 6. M4 模块四：数据可视化统计

**任务：**

- [ ] 总体 KPI 聚合接口（总投递/有效/挂简历率/笔试通过率/面试率/offer率）。
- [ ] 岗位维度通过率对比（柱状图 + 折线）。
- [ ] 时间维度投递量（日/周/月，柱状/折线）。
- [ ] 看板页面（指标卡 + 图表）。

**验收：** 数据实时反映投递/笔面试进度，图表可切换粒度。

---

## 7. M5 模块五：其他

**任务：**

- [ ] 话术库 CRUD + 分类 + 收藏 + 使用计数。
- [ ] 黑名单 CRUD + 类型 + 公司搜索。
- [ ] 每日看板：待投递/待复盘/待刷题聚合。

- [ ] 投递时黑名单提示接入。

## 8. M6 打磨与部署

**任务：**

- [ ] 全量数据导出/导入（JSON 备份）。
- [ ] 前后端联调、边界场景测试。
- [ ] 暗色主题、空状态、加载态、错误提示等体验优化。
- [ ] README、启动脚本（`start.bat` / `start.sh`）。
- [ ] 生产模式构建（前端 build，后端托管静态文件或分离部署）。

**验收：** 一键启动可用，数据可备份恢复，核心流程无阻塞 bug。

## 9. 风险与依赖

| 风险 | 说明 | 应对 |
|------|------|------|
| 状态机口径复杂 | 状态与通过率口径易混淆 | 用状态转移表驱动，文档统一口径 |
| Word 预览 | 浏览器不原生支持 | 后端转 PDF（LibreOffice/docx2pdf），环境缺失时降级为下载查看 |
| 简历预览体验 | 大文件加载慢、无翻页 | PDF.js 分页懒加载；转换结果缓存 |
| Offer 打分主观性 | 权重/映射需用户调优 | 提供可配置权重 + 快照保存，方便追溯 |
| 数据丢失 | 本地单库 | 提供一键导出备份、数据库文件备份说明 |
| 录音文件大 | 本地存储增长 | 文件落盘、可配置存储路径、可清理 |

## 10. 验收测试要点（核心场景）

1. 创建「开发岗」类型 → 新建简历版本并上传 PDF → 设默认 → 记录修改日志。
2. 录入一条投递（关联简历）→ 流转「已投递→进笔试」→ 跳转创建笔试 → 录入复盘。
3. 流转「进面试」→ 创建三面记录 → 记录问答与结果 → 上传录音。
4. 创建两个 Offer → 配置权重 → 生成对比与推荐。
5. 打开数据看板，确认各指标与图表正确。
6. 每日看板集成待投递/待复盘/待刷题，打卡后 streak 更新。
7. 投递黑名单公司时出现提示。
