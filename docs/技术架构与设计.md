# 技术架构与设计文档

> 配套 PRD 的技术实现方案。前后端分离，后端 Python。

## 1. 总体架构

```
┌─────────────────────────────────────────────┐
│              前端（Web SPA）                  │
│   Vue 3 + Vite + TypeScript + Element Plus    │
│   Pinia(状态) / Vue Router(路由) / ECharts(图表) │
│   Axios(HTTP)                                 │
└───────────────────┬─────────────────────────┘
                    │ HTTP / JSON (REST API)
┌───────────────────▼─────────────────────────┐
│            后端（Python）                      │
│   FastAPI + SQLAlchemy + Pydantic              │
│   分层：API → Service → Repository(ORM)        │
└───────────┬─────────────────────┬────────────┘
            │                     │
   ┌────────▼────────┐   ┌───────▼────────┐
   │   SQLite 数据库  │   │ 本地文件存储目录 │
   │ (单机轻量)       │   │ (简历/证书/录音) │
   └─────────────────┘   └────────────────┘
```

### 1.1 技术选型

| 层 | 技术 | 说明 |
|----|------|------|
| 后端框架 | FastAPI | 高性能、自动生成 OpenAPI 文档、Pydantic 校验 |
| ORM | SQLAlchemy 2.x | 数据建模与迁移（Alembic） |
| 数据库 | SQLite | 单用户单机，零部署；后续可平滑切换 PostgreSQL |
| 数据校验 | Pydantic v2 | 请求/响应模型 |
| 文件存储 | 本地目录 | `data/files/`，按类型分目录 |
| 前端框架 | Vue 3（组合式 API） | 现代前端框架 |
| 构建 | Vite | 快速构建/HMR |
| UI 组件库 | Element Plus | 表格/表单/日期/上传等现成组件 |
| 状态管理 | Pinia | 轻量状态 |
| 图表 | ECharts | 数据可视化、雷达图 |
| HTTP | Axios | 请求封装 |
| 语言 | TypeScript | 前端类型安全 |

> 备选：若偏好 React 生态，可将前端替换为 React + Ant Design，接口层不变。本文档默认 Vue。

### 1.3 分层设计（后端）

```
API 层（路由） → Service 层（业务） → Repository/ORM 层（数据）
```

- API 层：参数校验（Pydantic）、鉴权、响应封装。
- Service 层：状态机流转、Offer 打分、统计聚合等复杂业务。
- ORM 层：SQLAlchemy 模型与基本 CRUD。

## 2. 数据存储设计

> 详见《数据库设计文档》。此处概述：

- **SQLite** 存结构化数据；**本地文件目录**存二进制文件（简历 PDF/Word、证书、录音）。
- 文件表仅存 `file_path`，实际文件落盘 `backend/data/files/`。
- 采用时间戳统一 `created_at` / `updated_at`（UTC 存储，前端本地时区展示）——或本地时间存储（单机更直观，二选一，建议本地时间）。

### 2.1 简历文件预览实现方案

**PDF（原生支持，无需转换）：**

- 前端直接用 `<iframe>` / `<embed>` 指向 `GET /api/resumes/{id}/file` 内嵌展示；或用 PDF.js 实现自定义分页/缩放/翻页工具条。
- 后端该接口返回 `Content-Type: application/pdf` 并支持 `Content-Disposition: inline`（预览时）与 `attachment`（下载时）两种模式，用查询参数 `?disposition=inline|attachment` 区分。

**Word（.doc / .docx，需转 PDF）：**

三个方案按优先级推荐：

| 方案 | 依赖 | 说明 |
|------|------|------|
| 1. LibreOffice headless | 系统安装 LibreOffice | `soffice --headless --convert-to pdf`，转换质量高、稳定，推荐 |
| 2. Python 库（docx → pdf） | `docx2pdf`（Win 需 MS Word）/ `python-docx` + 渲染 | `docx2pdf` 依赖本机 Word；`.doc` 老格式支持弱 |
| 3. 纯前端库 | `@js-preview/docx` / `mammoth` | `mammoth` 转 HTML（排版可能损失）；`@js-preview/docx` 可预览 .docx |

**建议落地：**

- 后端提供 `GET /api/resumes/{id}/preview`：PDF 直接返回；Word 先查缓存目录 `data/files/cache/{resume_id}.pdf`，命中则返回，未命中调用转换命令生成后再返回。
- 转换结果按简历文件 `mtime` 或内容哈希做缓存失效，避免重复转换。
- v1 承诺：**PDF 必做；Word 预览提供（依赖 LibreOffice 或本机 Word），若环境缺失则降级为「下载后查看」**，前端需优雅降级提示。

## 3. API 设计约定

### 3.1 通用约定

- 前缀：`/api`
- 版本：暂不区分版本，`/api/v1`（预留，可直接 `/api`）。
- RESTful：资源 + HTTP 动词。
- 响应统一封装：

```json
{
  "code": 0,
  "message": "ok",
  "data": { }
}
```

- 分页：`?page=1&page_size=20`，返回 `{ items, total, page, page_size }`。
- 枚举值：字符串小写下划线（前端常量映射中文）。

| 模块 | 资源 | 主要端点 |

## 4. 核心业务逻辑设计

### 4.1 投递状态机实现

- 状态与合法流转关系以「状态转移表」驱动（枚举 + 邻接表），保证非法流转被拦截。
- 每次变更写 `application_status_logs` 流水。

```python
STATUS_TRANSITIONS = {
    "pending":   ["applied", "ended"],
    "applied":   ["resume_screening", "resume_rejected", "exam", "interview", "ended"],
    "resume_screening": ["resume_rejected", "exam", "interview", "ended"],
    "resume_rejected": ["ended"],
    "exam":      ["interview", "ended"],
    "interview": ["ended", "offered", "rejected"],
    "ended":     ["offered"],
    "offered":   ["rejected"],
    "rejected":  [],
}
```

### 4.2 Offer 打分算法

```
每维度得分 D_i ∈ [0, 100]
权重 W_i ∈ [0, 1]（用户可自定义，默认等权，可归一化）
总分 = Σ(D_i × W_i) / Σ(W_i)
薪资维度：年薪 → 按「理想年薪区间」线性/分段映射到 [0,100]
```

- 维度与权重可配置（存 `offer_weight_config`）。
- 对比接口输入多个 offer id + 权重，返回每个 offer 各维度得分、总分、排序与「最优推荐」标记。

### 4.3 统计聚合

- 从投递/笔试/面试/offer 表实时 SQL 聚合，或缓存预计算。
- 口径见 PRD 模块四；「有效投递」「通过率」等需统一分母定义。

## 5. 非功能实现要点

| 项 | 方案 |
|----|------|
| 文件上传 | FastAPI `UploadFile`，落盘到 `data/files/{category}/{uuid}.{ext}`，数据库存相对路径 |
| 文件预览 | 简历 PDF 用 `<iframe>`/`<embed>`/PDF.js 内嵌预览；Word（.doc/.docx）后端转 PDF 后按 PDF 方式预览（统一体验），转换结果落盘缓存 |
| 数据导出 | `GET /api/export` 生成 JSON 全量备份；数据库文件本身也可直接拷贝 |
| 敏感字段 | 账号密码明文存本地 SQLite（个人使用），前端提示；可后续加简单混淆 |
| CORS | 开发环境允许 `localhost` 前端端口 |
| 定时提醒 | 前端由看板/浏览器通知实现，后端可选提供「今日待办」聚合接口 |

## 6. 环境与运行

### 6.1 后端

```
cd backend
python -m venv .venv
.venv\Scripts\activate       # Windows
pip install -r requirements.txt
alembic upgrade head         # 初始化数据库
uvicorn app.main:app --reload --port 8000
```

### 6.2 前端

```
cd frontend
npm install
npm run dev                  # 默认 5173，代理 /api 到 8000
```

### 6.3 依赖清单（示例）

后端：`fastapi uvicorn[standard] sqlalchemy alembic pydantic pydantic-settings python-multipart aiosqlite`

前端：`vue vue-router pinia axios element-plus echarts typescript vite @vitejs/plugin-vue`

## 7. 里程碑划分（对应开发计划文档）

1. **M0 骨架**：前后端脚手架、数据库迁移、统一响应/错误处理。
2. **M1 模块一**：岗位类型、简历版本、修改日志、素材库、资产归档、文件上传。
3. **M2 模块二**：投递 CRUD、状态机、Offer 管理与打分对比。
4. **M3 模块三**：笔试、面试、题库、问答复盘、结果记录。
5. **M4 模块四**：统计看板与图表。
6. **M5 模块五**：话术库、黑名单、每日看板与打卡。
7. **M6 打磨**：数据导出、联调、测试、部署脚本。

> 具体任务拆解与工时见《开发计划与里程碑》文档。
