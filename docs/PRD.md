# 秋招辅助管理软件 — 产品需求文档（PRD）

> 版本：v1.0
> 作者：个人使用项目
> 状态：设计阶段（后续据此开发）
> 技术形态：前后端分离，后端 Python，本地单用户使用

---

## 1. 产品概述

### 1.1 背景与痛点

秋招求职过程链路长、信息分散、重复劳动多，个人常常面临以下问题：

1. **简历版本混乱**：不同岗位（算法/开发/测试/产品）需要不同简历，修改记录靠聊天记录或文件名，难以追溯「某一版投给了哪些公司」。
2. **投递信息零散**：公司、岗位、渠道、时间、进度散落在 Excel / 备忘录 / 聊天记录里，无法形成统一视图。
3. **进度不可视**：不知道自己投了多少、有效投递率多高、卡在哪个环节、短板在哪里。
4. **笔面试信息碎片化**：笔试链接、账号密码、面试时间、复盘记录分散，容易错过关键节点。
5. **Offer 决策靠拍脑袋**：多个 Offer 缺乏量化对比，凭感觉选择。

本软件是一款 **个人单机使用的秋招全流程辅助管理工具**，把「简历资产 → 投递 → 笔试 → 面试 → Offer 决策 → 数据复盘」串成闭环，帮助使用者系统化、可量化地管理秋招。

### 1.2 产品定位

- **用户**：单一使用者本人（单用户，本地使用，无需多租户/权限体系）。
- **定位**：个人求职过程的「CRM + 资产管理 + 决策辅助 + 数据看板」。
- **形态**：本地 Web 应用（浏览器访问），前后端分离。

### 1.3 核心目标（北极星指标）

- 让每一次投递、每一场笔试/面试、每一个 Offer 都有迹可循、可复盘、可量化。
- 首页一眼看到「今日该做什么」，数据页一眼看到「进度与短板」。

### 1.4 非目标（Not in scope，v1 不做）

- 多用户 / 团队协作 / 权限管理。
- 移动端原生 App（v1 仅做响应式 Web，桌面优先）。
- 自动抓取招聘网站数据（爬虫）。
- 复杂 AI 面试评估（可作为后续增强，非核心）。

## 2. 用户角色与使用场景

| 角色 | 说明 |
|------|------|
| 求职者（本人） | 唯一使用者，管理全部数据 |

**核心使用动线：**

1. 在【素材库】沉淀项目/实习/校园/证书等素材。
2. 在【简历管理】基于素材生成多个岗位版本简历，维护修改日志。
3. 在【投递管理】逐条录入投递，关联简历版本，流转投递状态。
4. 投递进入笔试/面试后，一键跳转到【笔试/面试管理】，记录时间、链接、账号，事后复盘。
5. 拿到多个 Offer 后，在【Offer 决策】按自定义权重打分，生成最优推荐。
6. 每天打开【今日看板】，完成待投递/待复盘/待刷题的打卡闭环。
7. 随时打开【数据看板】查看投递效率与各岗位维度通过率。

## 4. 模块一：个人简历及资产管理

### 4.1 多版本简历管理

#### 4.1.1 岗位类型管理

- 系统预置岗位类型：算法岗、开发岗、测试岗、产品岗。
- 支持**自定义新增 / 删除 / 修改**岗位类型（如：数据岗、运维岗、前端岗等）。
- 删除岗位类型时，若该类型下仍有简历版本，需提示并阻止或要求先迁移/删除关联简历。

**字段（岗位类型）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 主键 |
| name | str | 岗位类型名（唯一） |
| color | str | 展示用标记色（可选） |
| sort_order | int | 排序 |
| created_at | datetime | 创建时间 |

#### 4.1.2 简历版本管理

每个岗位类型下可维护多个版本简历（如「开发岗 v3 - 精简版」）。

**字段（简历版本）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 主键 |
| job_type_id | fk | 适配岗位类型 |
| version_name | str | 版本名，如「v3.1 精简版」 |
| target_position | str | 适配的具体岗位名，如「后端开发工程师」 |
| file_path | str | 本地文件路径（PDF/Word） |
| file_type | enum | pdf / doc / docx |
| file_size | int | 文件大小（字节） |
| status | enum | 草稿 / 使用中 / 已归档 |
| is_default | bool | 是否该岗位默认版本 |
| remark | str | 备注 |
| created_at / updated_at | datetime | 时间 |

#### 4.1.3 简历修改日志

- 每次修改简历后记录一条日志，**内容变更即记录**，形成修改时间线。
- 日志与简历版本关联，也可在简历详情页按时间倒序展示。

**字段（修改日志）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 主键 |
| resume_version_id | fk | 关联简历版本 |
| change_desc | str | 修改内容描述 |
| changed_at | datetime | 修改时间 |
| trigger_source | enum | 手动 / 同步（预留） |

**交互要点：**

- 简历列表按「岗位类型分组 + 版本时间倒序」展示。
- 支持上传本地 PDF/Word 文件；文件保存到后端指定目录。
- 支持设为某岗位默认版本，投递录入时自动带出。

#### 4.1.4 简历预览

- 简历版本详情页 / 列表点击均提供 **「预览」** 入口，无需下载即可在应用内查看简历内容。
- **PDF 预览**：浏览器原生渲染（`<iframe>` / `<embed>` / PDF.js），支持分页、缩放、翻页、下载。
- **Word 预览**（`.doc` / `.docx`）：后端转 PDF 后按 PDF 方式预览（统一体验）；转 PDF 方案见技术架构文档。
- 预览行为：
  - 右侧抽屉（Drawer）或弹窗内展示，避免跳离当前页面。
  - 预览器提供「打开原文件 / 下载」按钮。
  - 未上传文件的简历版本，预览按钮置灰并提示「请先上传简历文件」。
- 预览接口复用 `/api/resumes/{id}/file`（或独立 `/preview` 端点），Word 转换结果做缓存，避免每次重复转换。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 主键 |
| company | str | 公司名 |
| position | str | 岗位名 |
| city | str | 城市 |
| salary_min / salary_max | int | 薪资范围（K/月，可空） |
| salary_currency | str | 币种（默认人民币） |
| channel | enum | 投递渠道：BOSS直聘 / 牛客 / 官网 / 内推 / 其他（可扩展） |

### 5.2 投递状态机

状态流转（单向为主，允许部分回退，如误操作可撤销）：

```
待投递 → 已投递 → 简历筛选中 → 进笔试 → 进面试 → 已结束 → 已offer → 已拒
                  ↘ 挂简历
```

**状态定义：**

| 状态 | 含义 | 可流转去向 |
|------|------|-----------|
| 待投递 | 记录在案但尚未投出 | 已投递、已结束 |
| 已投递 | 已投出，等待反馈 | 简历筛选中、挂简历、进笔试、进面试、已结束 |
| 简历筛选中 | 简历筛选阶段 | 挂简历、进笔试、进面试、已结束 |
| 挂简历 | 简历未通过 | 已结束（可标记为终态之一） |
| 进笔试 | 进入笔试环节 | 进面试、挂（笔试挂→已结束）、已结束 |
| 进面试 | 进入面试环节 | 已结束、已offer、已拒 |
| 已结束 | 流程终止（未拿到 offer） | 已offer（少数可回流） |
| 已offer | 拿到 offer | 已拒（拒绝后） |
| 已拒 | 拿到 offer 后拒绝 | 终态 |

**状态流转记录（timeline）：**

每次状态变更，记录一条流水：`{ record_id, from_status, to_status, changed_at, note }`，便于追溯完整投放时间线。

**交互要点：**

- 列表支持按状态筛选、公司/岗位/城市/渠道搜索。
- 状态变更通过下拉或操作按钮完成，支持填写备注（如「笔试挂，原因：算法题没做出来」）。
- 「进笔试」「进面试」状态时，提供一键跳转到「模块三」对应记录的入口（见 6.0）。

#### 5.3.2 Offer 对比决策

- 支持同时选择多个 Offer 进行对比。
- 提供**可自定义权重**的打分模型，自动生成最优 Offer 推荐。

**打分维度（预置，可增删、可设权重）：**

| 维度 | 类型 | 说明 |
|------|------|------|
| 薪资 | 数值 | 由年薪（base×月数+绩效+签字费）自动折算为分 |
| 城市 | 数值/偏好 | 城市偏好打分 |
| 加班强度 | 数值 | 越低加班越好，可反向映射 |
| 行业前景 | 数值 | 1-5 |
| 公司规模 | 数值 | 1-5 |
| 岗位发展 | 数值 | 1-5 |
| 自定义维度 | 数值 | 用户新增，如「离家远近」「公积金」 |

**评分算法：**

- 每维度：`得分 = 该维度打分 × 该维度权重`。
- 总分：`Σ(维度得分) / Σ(权重)`，或直接 `Σ(维度得分)`（权重归一化后等价）。
- 薪资维度可将「年薪」按用户设定的理想年薪区间映射为 0-100 分（线性/分段）。
- 结果输出：每个 Offer 总分、各维度雷达图、**推荐排序**（最高分标记为「最优推荐」）。

**交互要点：**

- 权重可在设置页统一配置，也可在对比页临时调整。
- 对比结果可保存为快照（记录当时权重与分数），便于回看决策依据。

## 7. 模块四：秋招数据可视化统计

> 数据来源：投递、笔试、面试、Offer 数据实时聚合。

### 7.1 总体指标（核心 KPI）

| 指标 | 计算方式 |
|------|----------|
| 总投递数 | 投递记录总数（含待投递） |
| 有效投递数 | 已投递及之后状态的数量（排除「待投递」「已结束-未投」等） |
| 挂简历率 | 挂简历数 / 已投递数 |
| 笔试通过率 | 复盘通过数 / 已复盘笔试数 |
| 面试率 | 进入面试数 / 已投递数 |
| Offer 率 | offer 数 / 已投递数 |

> 口径细节在「数据口径说明」文档中明确。

### 7.2 岗位维度统计

- 按岗位类型（算法/开发/测试/产品）分组统计：投递数、进入笔试数、进入面试数、offer 数、各环节通过率。
- 产出对比图（柱状图 + 通过率折线），帮用户识别「哪个岗位方向转化更好」。

### 7.3 时间维度统计

- 每日投递量（柱状图）。
- 每周投递量趋势（折线图）。
- 可切换日/周/月粒度，查看投递节奏。

### 7.4 图表实现

- 前端图表库：ECharts（或 Chart.js），雷达图（Offer 对比）、柱状图、折线图、饼图。

## 9. 全局非功能需求

| 项 | 要求 |
|----|------|
| 数据本地化 | 数据存储在本机，文件保存在本地目录 |
| 单用户 | 无需登录/权限体系（可预留简单访问口令保护，可选） |
| 响应式 | 桌面优先，兼顾移动端 | 
| 数据备份 | 支持一键导出 JSON / 数据库备份 |
| 性能 | 单用户数据量（数千条），轻量即可 |
| 安全 | 账号密码等敏感字段本地存储，明确提示；文件本地保存 |
